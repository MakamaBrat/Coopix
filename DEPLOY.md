# Coopix Market на Vercel: сайт + бэкенд + Supabase

```
Telegram Mini App ──► Vercel (один проект, один домен)
                       ├─ public/   статический сайт
                       └─ api/      серверные функции  ← здесь живут ВСЕ ключи (переменные окружения Vercel)
                                         │ service_role
                                         ▼
                                   Supabase: Postgres, таблица submissions
```

Сайт ходит на свой же `/api/...`: адрес Supabase и ключи браузеру не видны, CORS не нужен.
В файлах проекта ключей нет, их нужно задать только в Vercel.

## 1. Supabase (только база)

1. Создайте проект. Откройте **SQL Editor**, вставьте `supabase/schema.sql` и выполните.
2. **Project Settings → API** → скопируйте **Project URL** и ключ **service_role** (секретный).
   Ключ `anon` не нужен: к таблице у него доступа нет.

> **Обновляете существующий проект?** Выполните `supabase/schema.sql` в SQL Editor ещё раз: он дописывает
> таблицы `users`, `moderators`, `settings` и функцию `touch_user`. Старые данные не затрагиваются.

## 2. Бот

@BotFather: `/newbot` → токен. Свой Telegram id возьмите у @userinfobot.

## 3. Переменные окружения Vercel

Project → **Settings → Environment Variables**. Для каждой отметьте **Sensitive** и окружения
Production и Preview. Это единственное место, где лежат ключи.

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен бота: проверка подписи Telegram и отправка уведомлений |
| `SUPABASE_URL` | Project URL из шага 1 |
| `SUPABASE_SERVICE_KEY` | ключ `service_role` из шага 1 |
| `ADMIN_IDS` | Telegram id админов через запятую, например `123456789,987654321` |
| `INITDATA_MAX_AGE` | необязательно, секунд, по умолчанию 86400 |

Не добавляйте префиксы `NEXT_PUBLIC_` / `VITE_` / `PUBLIC_`: переменные с ними попадают в браузер.
Из CLI: `vercel env add BOT_TOKEN production` (значение вводится в запросе, в файл не пишется).
После изменения переменных нужен новый деплой (Deployments → Redeploy).

## 4. Деплой

Импортируйте репозиторий в Vercel (Framework Preset: **Other**, Build Command пустой, настройки уже в
`vercel.json`) или выполните `npx vercel --prod` в папке проекта.

## 5. Подключить к боту

@BotFather → `/newapp` (или Menu Button) → URL вашего проекта, например `https://coopix-market.vercel.app`.

## 6. Проверка

1. `https://ВАШ-ДОМЕН/api/health` → `{"ok":true,...}`. Если `false`, видно, какой переменной не хватает
   (значения не показываются).
2. Откройте Mini App из Telegram: у админа в профиле появится «Админ-панель».
3. Отправьте тестовую игру → в админке смените статус → автору и админам придёт сообщение от бота.

## Админ-панель

Адрес: `https://ВАШ-ДОМЕН/admin.html`. Открывается из Telegram: в профиле у админа и модератора кнопка «Админ-панель».
Личность проверяется по подписанному `initData`, права решает сервер, а не страница.

| Роль | Как назначается | Что может |
|---|---|---|
| Главный админ | переменная `ADMIN_IDS` в Vercel | всё: пользователи и баны, заявки, новости, адрес в «Помочь», команда |
| Модератор | вкладка «Команда» (добавляет главный админ) | только заявки на игры |

- **Пользователи**: список с датой регистрации и последней активности, поиск, фильтры, статистика, бан и разбан с причиной.
  Игрок попадает в список при первом заходе после обновления (его дата регистрации = первый заход).
  Забанить можно только обычного игрока: себя, главных админов и модераторов нельзя.
- **Бан**: сайт при запуске запрашивает `/api/config`, забаненный получает 403 и видит экран «Доступ ограничен»
  с причиной, маркет не загружается. Сервер также закрывает ему все остальные `/api/...`, в том числе отправку заявок.
- **Новости**: до 10 штук, у каждой тег, цвет, дата, заголовок, текст и необязательная ссылка (только `https://`).
  Нет ссылки = новость не нажимается. Порядок меняется стрелками. Изменения сразу видны игрокам.
- **Помощь · донат**: адрес USDT (TRC20) с проверкой формата. При смене бот присылает уведомление всем главным
  админам: старый и новый адрес.
- **Заявки**: те же статусы и комментарии, что и раньше. Автору приходит сообщение от бота.

Новые маршруты: `GET /api/config`, `GET /api/admin?r=stats|users|news|wallet|team`, `PATCH /api/admin?r=user&id=…`,
`PUT /api/admin?r=news|wallet`, `POST|DELETE /api/admin?r=team`. Права на каждом проверяются на сервере.

## Безопасность (что и зачем)

- **Личность** только из подписанного `initData`; `authorId` из тела запроса игнорируется. Проверка подписи
  усилена: `auth_date` обязателен, сравнение за постоянное время, подпись из будущего отклоняется.
- **Главный админ** определяется на сервере по `ADMIN_IDS`, модераторы по таблице `moderators`; сайт узнаёт про права через `GET /api/me`.
- **Таблица закрыта**: RLS без политик, у `anon`/`authenticated` прав нет. SQL-функция `create_submission`
  тоже закрыта (`revoke ... from public, anon, authenticated`), вызвать её может только `service_role`.
- **Лимит 5 заявок в сутки** считается в базе в одной транзакции с блокировкой по автору: пачкой параллельных
  запросов его не обойти.
- **Ошибки**: клиент получает только `server_error`, детали Postgres и Telegram остаются в логах Vercel.
- **Чужой HTML** в админке запускается в iframe с `sandbox="allow-scripts"` без `allow-same-origin`:
  у кода игры нет доступа к приложению и `initData` админа.
- Рекомендую включить в Vercel → **Firewall** правило Rate Limit для путей `/api/*`.
- Если токен бота или ключ Supabase когда-либо лежали в файле, чате или репозитории, перевыпустите их
  (`/revoke` в @BotFather, Rotate в Supabase) и обновите переменные.

## Сообщество: отзывы, профили, посты, счётчики, журнал

Выполните `supabase/schema.sql` в SQL Editor ещё раз: он добавит таблицы `profiles`, `reviews`, `events` и функции
`game_stats`, `activity_series` (RLS включён, прав у `anon`/`authenticated` нет, работает только `service_role` из функций Vercel).
Маршрут один: `/api/hub?r=stats|reviews|avatars|profile|post|track|activity|feed`.

- **Рейтинг** игры = среднее по оценкам в отзывах, менять его вручную нельзя. Один отзыв на игрока и игру (повторная отправка правит его).
- **Счётчики** «Играли / Скачали» считают и игроков (разных людей), и все нажатия. Нажатие «Скачать» считается, даже если файл ещё не добавлен.
- **Профиль игрока** открывается по нажатию на аватар или ник в отзыве и в журнале. Telegram id наружу не отдаётся: вместо него непрозрачная строка (AES от секрета бота).
- **Пост**: один на игрока (заголовок до 60 и описание до 600 знаков), админ и модератор могут его удалить.
- **Журнал действий**: каждая строка = действие с временем. Нажатия (заход, открытие, запуск, скачивание, избранное, карточка) шлёт клиент
  с паузами и лимитом 300 в час; отзывы, посты, профиль, медали, уровни и заявки пишет только сервер. График «Активность → ресурс» строится из журнала.
- Вес действий в COOP: `WEIGHTS` в `api/_lib/hub.js`; цена COOP: `CAP.price` в `public/index.html`.
- Общие данные ведут только встроенные игры (`built`); свои карточки в браузере остаются локальными.

## Каталог игр, обложки, фон, моды, «Спасибо автору»

**После обновления заново выполните `supabase/schema.sql` в SQL Editor.** Повторный запуск безопасен. Добавятся таблицы `games`, `game_edits`, `game_mods`, `thanks` и функция `thanks_stats`, а `activity_series` обновится.

- **Каталог.** Список игр хранится на сервере. Менять карточку (название, теги, обложку, фон, доступ) может только главный админ: карандаш на карточке, изменения сразу видят все. Поле «Кто видит игру»: все / только админы / скрыта.
- **Авторы.** Автор опубликованной игры видит карандаш только на своей игре. Его правки (описание, версия, ссылка, обложка, фон, оформление) уходят админу. Админ одобряет их в разделе «Правки страниц», текущее и новое показаны рядом.
- **Публикация.** Админ-панель → Заявки → «Опубликовать в маркет», сразу всем или сначала только админам.
- **Обложка.** Хранится на сервере в 512×512 хорошего качества. У браузера есть кэш до ~3 МБ.
- **Фон.** Отдельная картинка 1280×720 для карточки и страницы игры. Эффект ложится поверх неё слабым слоем.
- **Моды.** На странице игры переключатель «Отзывы | Моды». Игрок предлагает мод одним HTML-файлом до 1,5 МБ, одновременно на проверке не больше трёх. Админы и модераторы проверяют в разделе «Моды». Одобренный мод показывается с автором и кнопками «Играть» (в изолированном iframe) и «Скачать».
- **«Спасибо автору».** Оплата звёздами Telegram (XTR), от 10 до 500 ⭐. Сумма видна на карточке золотой меткой со «слитками», на странице игры и на графике.
  - Подключите приём один раз: Админ-панель → «Звёзды» → «Подключить приём звёзд». Это регистрирует вебхук `/api/bot` с секретом, который выводится из `BOT_TOKEN`.
  - Звёзды приходят на баланс бота проекта, автору они засчитываются в статистике. Выплату автору делаете вы.
- **Сортировка и фильтры магазина.** Под поиском можно сортировать: как в каталоге, по оценкам отзывов, по поддержке авторов, по числу запусков, по числу отзывов. Есть фильтры «★ 4 и выше» и «с поддержкой». Выбор запоминается.
- **Два рейтинга не путаются.** Оценки отзывов показываются звёздами 1–5. Поддержка авторов показывается золотыми пиксельными блоками 1–5 в строке жанра на карточке; ступени 1 / 100 / 500 / 2000 / 10000 звёзд Telegram. Точная сумма видна на странице игры.
- **Журнал действий** виден только админам и модераторам: сервер отдаёт `hub?r=feed` только им.
- **График** показывает действия (столбцы), звёзды авторам (золотые звёзды) и капитализацию (линия). Он рисуется в реальную ширину экрана и помещается в окно без прокрутки.

## Тесты

```bash
npm install && npm test
```

51 тест (3 из них про обработчики запускаются после `npm install`): подпись initData, роли (главный админ / модератор / игрок), бан и разбан, защита админов от бана,
валидация новостей и адреса доната, команда, валидация заявок, лимит, видимость чужих файлов, поведение
обработчиков без окружения и при недоступной базе.

## Что осталось локальным

Профиль и XP, отзывы, избранное и счётчик загрузок по-прежнему в `localStorage` (см. `public/README.txt`).
Для общих отзывов и реальных скачиваний понадобятся отдельные таблицы и маршруты по тому же шаблону.
